# Prometheus

## Overview

**Prometheus** is an open-source monitoring and alerting toolkit designed for collecting, storing, and querying time-series metrics.

It is the **de facto standard monitoring solution for Kubernetes** and is a graduated project under the **Cloud Native Computing Foundation (CNCF)**.

Prometheus continuously collects metrics from Kubernetes components, applications, and infrastructure, enabling administrators to monitor system health, troubleshoot issues, and trigger alerts based on predefined conditions.

Administrators gain complete visibility into cluster and application performance.

# How Prometheus Works

1. Applications expose metrics through an HTTP endpoint (usually `/metrics`).
2. Prometheus periodically **scrapes** these endpoints.
3. Metrics are stored in a built-in time-series database.
4. PromQL is used to query the collected metrics.
5. Alertmanager sends notifications when alert rules are triggered.
6. Grafana visualizes the metrics using dashboards.

# Core Components

## Prometheus Server

- Collects metrics
- Stores time-series data
- Executes PromQL queries

---

## Exporters

Exporters expose metrics from systems that don't natively provide Prometheus metrics.

Common exporters include:

- Node Exporter
- kube-state-metrics
- Blackbox Exporter
- MySQL Exporter
- PostgreSQL Exporter

---

## Alertmanager

Alertmanager handles alerts generated by Prometheus.

It can send notifications through:

- Email
- Slack
- Microsoft Teams
- PagerDuty
- Webhooks

---

## Grafana

Grafana connects to Prometheus to create dashboards and visualize collected metrics.

# Install Prometheus

Add the Prometheus Helm repository:

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts

helm repo update
```

Install Prometheus:

```bash
helm install prometheus prometheus-community/kube-prometheus-stack
```

Verify installation:

```bash
kubectl get pods
```

---

# Access Prometheus

Port-forward the Prometheus service:

```bash
kubectl port-forward svc/prometheus-operated 9090:9090
```

Open:

```text
http://localhost:9090
```



# Prometheus vs Metrics Server

| Prometheus | Metrics Server |
|------------|----------------|
| Long-term monitoring | Real-time metrics only |
| Stores historical data | No historical storage |
| PromQL support | No query language |
| Alerting | No alerting |
| Visualization through Grafana | No dashboards |
| Comprehensive monitoring | CPU and Memory only |

---

# Prometheus vs Grafana

| Prometheus | Grafana |
|------------|----------|
| Collects and stores metrics | Visualizes metrics |
| Time-series database | Dashboard platform |
| Supports PromQL | Supports multiple data sources |
| Generates alerts | Displays dashboards |

---

# Advantages

- Powerful time-series database
- Kubernetes-native monitoring
- Built-in alerting
- PromQL for advanced queries
- Large ecosystem of exporters
- Easy integration with Grafana

---

# Limitations

- Local storage is not intended for long-term retention without additional solutions.
- High-cardinality metrics can increase memory usage.
- Requires exporters for many external systems.
- Dashboard creation is handled by Grafana, not Prometheus.

---

# Best Practices

- Use Prometheus with Grafana for visualization.
- Configure Alertmanager for critical alerts.
- Monitor only necessary metrics to reduce storage usage.
- Use recording rules for frequently executed queries.
- Secure Prometheus endpoints using authentication and network policies.
- Regularly back up important configurations.
